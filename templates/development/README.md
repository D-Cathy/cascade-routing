# 10—20 条真实开发任务采集与标注模板

本目录是未填草稿，不是真实样本。提供 15 个任务槽位、45 条调用和45条标签槽位；可缩至10条或扩至20条。它们只用于接口检查、试标和开发，不占用正式校准/测试集，也不足以完成论文 E0 的约100条开发任务目标。

1. 按五类任务填入材料、问题、固定证据、输出要求、硬约束与正确的“信息不足”响应。先建立来源卡，再定义来源组、模板家族、近重复关系。所有模型共享原始问题和证据，禁止传递已有答案。
2. `dev_fit/dev_eval` 当前仅为占位分配：按真实来源组重排并在评估前锁定；同组改写、三模型输出、网络变体与重复测量不得跨划分。来源独立性需人工核查，字符串不同不是独立性的证明。
3. 填部署表，固定版本、聊天模板、解码和512 token初始上限。采集器须只尝试一次，失败也占用该模型机会。原 `APIQuery` 存在多层重试，不能直接用于本协议。现有单次HTTP适配器已通过模拟测试，但真实部署尚未验收；操作见../../docs/single_task_loop.md。
4. 保存原始答案、在线格式检查结果和完整单调时钟时间戳。失败检测、取消、已发生费用均保留；`UNATTEMPTED` 不是 `FAILED`。真实未知费用/耗时使用 null 和 missing，不用0填补。paid_fee、GPU占用、传输字节与归一化成本分列，费率来源/日期必须记录。
5. 单模型独立采集延迟不能自动代表序贯调用延迟；回放入口目前仅是静态串行工程验证。真实链路、排队与取消需专门测量。
6. 标签只填 `labels.draft.jsonl`，参考答案与标注依据仅放该文件，不放问题、证据或 controller environment。向标注者导出匿名答案卡，隐藏模型、策略和成本；模型映射由评估人员保管。
7. 开发样本先双人试标。三个维度各0—4分：事实/约束正确性、必要信息完整性、要求遵循。`Q=(0.5*s1+0.3*s2+0.2*s3)/4`；重大错误或硬约束否决覆盖为0。valid独立记录；达标为 valid 且 Q>=任务阈值。保存初评、复评、裁定、证据位置与规则版本；随机复核至少20%，临界值±0.05、疑似重大错误及分歧额外复核并分列。
8. 未裁定质量保留null，不删除请求。本轮工具输出未知结局和失败率上下界；论文正式主分析对仍无法裁定标签保守计失败及敏感性分析，尚未实现该正式模式。
9. 删除草稿标记，另存填好的 JSONL，复制配置并修改路径。先 `--validate-only`，再回放。模板中的null会故意导致校验失败，避免空模板被当成数据。

预算、时限与成本单位须来自开发测量/预声明研究设置。模型实际部署地址、云模型、付费授权、归一化尺度和领域复核人仍待提供。不要把密钥写入任何模板或日志。

单条闭环新增 `single_task.draft.json` 与 `configs/single_task_live.template.json`；先补齐信息，再按 [单条任务步骤](../../docs/single_task_loop.md) 校验、采集、匿名双人评分与独立评价。
