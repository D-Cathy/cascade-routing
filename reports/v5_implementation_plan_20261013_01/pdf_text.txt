1. 目标、依据与关键决策
目标是在已有 Cascade Routing 仓库上，实现 v5《面向船舰智能信息服务的风险约束多目标路由与动态升级》的
完整控制器，并组织能检验其创新机制的 E1–E6 实验。工作重点是训练轻量预测器、构建经验转移库、实现滚动
规划和完整策略校准；不以重新训练或微调 Qwen 大模型为核心。
推荐架构：保留原选择算法作对照，复用统一执行框架，新增独立 v5 方法模块。 不把原 CascadeRouter 的“模
型集合期望质量减成本”搜索直接改名为 v5 动态规划。两者的状态、目标、转移、风险筛选和执行语义不同。
依据优先级：papers/v5_eng.pdf 与 v5_zh.pdf 的方法第 3 节、实验第 4–5 节及附录 A 为本计划主规范；现有论
文阅读报告用于定位；父目录论文初稿仅作补充核对。当前 PDF 报告固定 11 条策略、E1–E6、12 秒时限、1.50
预算、Qwen2.5 三模型。较早 TeX 中至多 54 条候选等设计不混入本次主复现。
本文区分三类内容：论文规定是需要实现的目标；现有实现是当前源码可确认的能力；实施建议是为补齐接口、
验证和可复现性提出的方案。以下新文件名和 CLI 均是计划设计，尚不可直接运行。论文既有表格数值不是本地
已复现结果，也不是调参目标。
两条待验证主张：C1，完整方法在完整服务质量、时限和预算要求下，相比受限 Cascade Routing 改善资源折
中；C2，收益增强检索、联合采样和多步前瞻各有独立增量。反向解释也须排除：收益仅来自更强预测器、更多
调用、更宽松失败口径或漏记控制开销。

3. 数据建设：现有缓存能用到哪里
RouterBench 两个 CSV 及 classification、free_form、code_math、swebench 的 JSON 可用于读取适配、特征
管线、接口回归和公开基准对照。它们缺少 v5 五类领域任务、完整时间索引链路过程、统一归一化成本和领域评
分卡，不能直接支撑 v5 主实验。
尤其不能把 SWE-Bench 的解决标志当作一般在线输入；其测试缓存 model_answers 可能已经包含事后是否解
决。代码数学的 token 数乘模型规模与 RouterBench 的货币费用、SWE-Bench 的秒数必须分别标注，不可直接
拼接成 v5 的成本。

3.3 顺序资源不能由三个独立耗时拼出
复用 single_task.collect 采集三模型输出，明确它是独立固定模型采集。重建合法历史可复用独立回答，但调用
资源必须按策略实际起始时刻读取时间索引环境。中断链路要能在请求窗口内恢复；不是简单将云端永久设为
unavailable。
拟新增 TraceReplayBackend：输入动作、当前逻辑时钟和只读轨迹句柄，返回该时间位置下的结果与资源。控
制器只看到当前环境；轨迹全貌只在后端。若调用改变排队状态，静态缓存不足，须实际执行对应链或使用单独
验证的负载回放系统。不能通过按带宽比例直接缩放所有推理和排队时间来伪造测量。

5. 状态、动作与执行接口的详细修改
5.1 可观察状态与规划代理分开
ObservableState 目前有问题、证据、成功/失败字典、剩余资源和静态环境。拟补充有序 AttemptObservation
序列，包含模型、状态、答案引用、在线检查、预测质量、长度、可观察时戳、已付资源。顺序显式保存，不依
赖字典偶然顺序推断历史类型。
新增 PlanningState 仅用于搜索：当前问题表示、有效历史摘要、动作掩码、剩余资源、当前环境。供体 ID 可用
于诊断，但不能成为决策特征；reference_quality、参考答案、未来网络、未调用输出禁止进入状态或可观察状
态键。真实答案句柄与代理摘要用不同类型，ACCEPT 只能返回真实已调用且有效的答案。
动作沿用 CALL(model)、ACCEPT、FAIL。初始任一获准模型；后续严格向上且允许跳级，每模型最多尝试一
次，失败也占次数。模型输入始终是同一原始 question/evidence，历史回答只提供给控制器。

5.2 评分与最终答案保留
拟接口：QualityScorer.score(question, evidence, answer, model, checks) → q_hat；
SuccessScorer.predict(selected_answer_features, state) → p_ok；Selector.select(history) → 真实答案句柄
或空。
仅在有效回答中按 q_hat 最大选择；同分选择最早返回答案。失败/无效输出不候选，但尝试与资源保留。初始无
答案时质量与达标概率为零，不凭空 ACCEPT。编码、规则验证、选择和评分时间均计入控制开销；缓存命中也
计实际查询时间。

5.3 资源与环境接口
ResourceLedger 同时保存 fee、paid_fee、GPU 占用秒、上传/下载字节、归一化 cost、来源与完整性。PDF 主
口径为 C=累计[0.5F/F0+0.5V/V0]；F0/V0 和自托管占用费率只能在训练/预声明规则下确定，随后冻结。能源不在
PDF 主公式内，不额外悄悄加项。
真实总时延为请求到终止的单调时钟差；分项 up/queue/infer/down/verify/control 用于解释，不重复相加。回
放用逻辑时钟加调用资源与控制耗时，计时模式在报告中明确。若用实测控制时间驱动回放时钟，语义可能受机
器负载影响；开发阶段确定可复现的计时方案，实际执行 E6 则始终报告真实墙钟。
网络中断、未知费用、解析失败、超时等不得隐式重试。现有 SQLite 尝试账本保留；增设实验运行身份与逻辑请
求身份，明确 E6 多策略对应不同服务请求，而非同一请求重复发送。此扩展须有独立运行 manifest，不能通过
换 ID 规避已发生的同请求尝试限制。

6. 预测器训练的具体方案
6.1 文本表示：冻结编码器与 D_Q-only PCA
使用 PDF 所述多语言 MiniLM-L12-v2；完整权重标识/修订号在 PDF 未充分报告。实施建议候选为 sentence-
transformers/paraphrase-multilingual-MiniLM-L12-v2，最终须核实权重来源与 SHA256 后冻结，不能把建议
标识称为已确认原实验权重。
问题与固定证据按固定字段顺序拼接，答案单独编码，分别截取前 128 token，各自 PCA 到 32 维。PCA 仅拟合
D_Q，训练不足秩时下调并记录；规则检查读取完整文本。空答案零向量/零长度/零评分并附 missing 标志。记
录长文本截断比例，训练后不能改变截断规则。

6.2 质量回归与达标分类
HistGradientBoostingRegressor 预测参考质量，平方损失，输出 clip 到 [0,1]。HistGradientBoostingClassifier
预测当前保留答案“有效且 Q≥0.80”的概率，标签与质量回归分开。按冻结评分器从可见历史选出的答案构建
训练对象，不能用真实最高质量答案替代。
PDF 表 9 初值：200 轮、学习率 0.05、最多 15 叶、最小叶样本 20、L2=1.0；关闭内部随机提前停止，按任务组
调参。输入包含问题/答案降维表示、模型身份、长度与确定性检查；达标分类按论文状态接口加入可观察信息。
训练状态扩增按任务等权，避免历史多的任务支配损失。
开发诊断包括 MAE/RMSE、Brier 分数、可靠性图、门槛附近误差、分任务类型误差与选择后质量。单类别或缺
失特征的回退规则在冻结前写入配置；未确定时禁止正式运行，不临时用测试标签补训练。

6.3 条件升级收益
在 D_Q 评分器冻结后，利用 D_G 中合法调用顺序重建历史。对每个当前状态 s 和候选模型 m，使用相同
Selector 计算调用前后真正保留的答案，再用评估侧参考质量生成标签。
收益标签 = 调用后所保留答案的参考质量 − 调用前所保留答案的参考质量。 无有效答案按零处理。每候选模型训
练一个平方损失梯度提升回归器，输入含任务表示、历史预测分/检查/状态、剩余资源和当前环境。负标签必须
保留，不能截成非负；也不能用两个模型平均准确率之差代替。
收益向量在已尝试或未获准的槽位填零，并另给动作掩码。收益只增强检索距离，不直接替代规划质量或失败分
量；不因预测收益≤0删除所有对应调用分支。

6.4 训练产物必须可追溯
输出 encoder_manifest、pca_question、pca_answer、feature_schema、quality_model、
success_model、gain_models、training_manifest。各产物记录拟合任务/来源组、库版本、种子与哈希。用
“冻结后改变 D_C/D_T 标签，产物和在线动作保持不变”的泄漏测试验证接口。

7. 收益增强检索与联合转移：创新模块一和二
7.1 历史库记录与检索
每条 D_G 记录含安全的调用前状态、候选模型、返回类型、预测摘要、资源增量、后环境，以及仅离线可见的训
练标签。实际传给在线检索的库导出文件剔除参考质量；不能把完整训练表直接传给 Policy。
先按候选模型、已尝试集合、按顺序排列的结果类型过滤；再计算标准化距离。基础特征与预测收益各按训练数
据确定尺度，拼成“标准化状态特征 + κ×标准化收益向量”；正式初值 κ=1。每来源组保留最近一条记录，同距
按固定 record_id；最多取 20 组，少于 5 组不支持该动作。
距离权重按 PDF 式 3.12 的核权重归一化；表 9 规定核宽为近邻距离中位数，下限 10⁻⁶。按调用模型在 D_V 估计
最近邻距离的 0.99 分位数作为支持阈值；尺度与阈值来源写入 manifest。动作距离超过固定支持阈值时只剔除该
动作，不连带删除其他动作。报告支持率、邻居组数和回退率，否则无法判断数据是否支撑规划。

7.2 联合采样及状态映射
每动作按归一化邻居权重有放回抽取 B0=4 条完整记录。抽样后重复记录合并，场景权重=出现次数/4，总和必须
为 1；不能再乘一次原邻居权重。
保留答案结果块与资源—环境块的联合关系。代理状态保持当前问题，移植供体答案压缩摘要、可观测检查与资
源，然后重新计算当前评分/状态。遵守 PDF 表 2 的字段映射，不移植供体真实参考质量，不把代理文本当真实
答案返回。实际调用回来后，代理由真实反馈完全覆盖。
同一可观察状态下所有场景必须共享后续动作；状态键包含未来决策所需的可观察信息，但不得夹带供体 ID 或隐
藏标签来人为区分场景。只做前沿向量网格压缩，不以网格化粗暴合并实际资源状态。

7.3 随机性和保守缓冲
SHA256(请求 ID、规范状态、动作、策略版本、全局种子) 的前 64 位作为冻结 PCG64 种子；请求 ID 不进入模型
特征。固定字段顺序、浮点 hex 与缺失标志，不使用 Python 随机化 hash。固定条件下重复运行应重现邻居、抽
样和首动作。
D_V 上用任务等权误差的 0.95 分位数得到 rQ、rL,m、rC,m，缓冲至少为零。质量保守值=max(0,q_hat−rQ)，资
源上界=预测均值+对应缓冲；样本不足组退回全局缓冲。停止门阈值与质量缓冲须满足 τ+rQ≤1，否则该候选配
置开发期即剔除。它们是经验缓冲，不是任意在线状态的覆盖保证。

8. 多目标有限深度规划：创新模块三
8.1 递推对象和动作价值
每候选保存四维向量、首动作及按子状态键排序的续行指针。四维均最小化：最终质量损失、未来时延、未来开
销、预测失败概率。
动作       向量/处理                       允许条件
ACCEPT   (1−q_hat, 0, 0, 1−p_ok)     有真实有效答案、保守质量通过停止门、实际资源未超限
FAIL     (1, 0, 0, 1)                失败终止；已付资源仍保留
 动作            向量/处理                         允许条件
 CALL(m)       对场景的“子前沿 + 该次资源增量”按概率加权合并     权限/顺序/单次尝试合法，支持充足，预测资源可行

深度由剩余可调用模型数量确定，最多三次尝试。四维向量保存的是剩余价值；累计实际资源单独在状态与账本
中，避免重复加算。终止向量的零资源不是把之前已花资源清零。

8.2 非支配前沿和确定性压缩
逐场景按固定状态键顺序做加权交叉和，每步删除被支配方案。完全相同可观察状态共享续行选择；不能让规划
器根据供体标签选择不同未来动作。为保留首动作来源，不得只保存四个浮点数后再猜动作。
按 u=(v1,v2/d,v3/b,v4) 与 ε=0.02 网格分箱，每格保留实际向量，最多 32 项。格内排序遵从 PDF：是否超过 ρ、
J、失败代理、开销、时延、首动作编码、续行序列；相同向量按同一规则去重。浮点使用固定 float64，不加入
未声明容差。
最后筛选 v4≤ρ，再最小化 J=质量损失+λL×时延/d+λC×开销/b。J 同分按开销、时延、动作编码、续行序列排
序。ρ 每轮重用，是预测规划阈值，不是传给分支的剩余风险预算。

8.3 滚动执行与异常处理
规划只执行首动作。实际返回后更新时钟、账本、在线有效性、评分、环境，再从新状态规划。控制器超时、无
合法调用或筛选前沿为空时：当前答案满足停止门且实际资源未超限则接受，否则失败。单个动作不受支持时先
评估其他受支持动作。
新增 planning_timeout、unsupported_action、empty_frontier、gate_rejected 等诊断事件，但服务失败仍
按统一四事件并集计算。每轮控制限时按 PDF 表 9 为 min(0.02×请求时限, 50 ms)，主设定为 50 ms；需要在检
索、递推交叉和等耗时环节主动检查截止时间并执行冻结回退，超时本身的耗时也计入总账。记录初始计划与实
际续行分歧率；不把初始预测路径当成最终执行路径。

8.4 先证明递推实现正确，再测收益
构造微型状态树，以不压缩的穷举策略枚举为参考，与前沿递推比较向量和首动作。覆盖负收益、失败、无效、
相同可观察状态、不同资源、重复场景、零剩余预算。随后开启压缩，记录丢失候选数和首动作变化。这是代码
验证，不是实际系统全局最优性证明。

10. 校准、冻结与统计口径
冻结包包含模型/PCA/特征定义、转移库、标准化、缓冲、支持阈值、偏好、停止门、ρ、种子规则、前沿压缩、
超时回退、后端与资源配置。生成 policy_manifest.json 与每个产物哈希；校准/测试发现哈希变化即拒绝继续作
为同一策略结果。
按 PDF 复现，D_V 先结束模型选择，冻结九主配置和两机制变体，H=11、δ=0.05、α=0.10。每条完整策略在
D_C 执行闭环，失败数 k、独立单元数 n 给出单侧 Clopper–Pearson 上界；k=n 时上界为 1。筛选用未四舍五入
值，不能经验失败率达标就顶替上界要求。
上界 = Beta 分布在 1−δ/H 位置的分位数，参数为 k+1 和 n−k。 这是一条冻结策略完整服务失败风险的统计检
验，不是预测器概率校准，也不能用近邻样本数替代 n。
来源组独立性、可靠标签与同分布采样不清楚时，输出 binomial_reference_only，不能宣称部署风险保证。
PDF 固定类别配额的局限也要保留。若开展新的确认性试验，可预先按独立来源组抽样，或预声明分层权重与分
层上界方案；这是新增协议，不与旧 PDF 数值复现混报。
候选数量若增到多个运行点或多个训练种子，应在校准前用实际总 H，或声明不同分析族和置信预算，不能继续
套 11。测试后挑种子会破坏选择控制。默认先冻结一个主训练种子；另两个种子仅作预声明稳健性扩展，若也要
保证须计入候选族。
现有 metrics 对缺失资源/标签保留 null，有利于开发诊断，不能全局改成失败或零。本计划新增正式报告模式：
PDF 附录要求未解决终局标签保守计失败并单列；未知资源仍保留 unknown，不伪造均值。正式风险报告可单列
保守失败上界，但资源不完整时不得宣称完整资源比较完成。完整性验收先于主表导出。
测试描述性失败区间与校准单侧上界分开。实施建议新增按来源组 2000 次配对 bootstrap 给开销/质量/时延/失
败差区间；这超出 PDF 仅描述性报告，须标为本次新增分析。重复轨迹不增加独立 n。没有有效答案 Q=0；全部
请求入分母，失败资源保留，四类失败可重叠。

E1 主比较：整体资源折中

一化成本，伴随质量、失败数、均值/P95 时延、有效返回率。比较重点是完整方法与 cascade_reference；质量
下降或失败增加时明确呈现代价，不只报节省百分比。
成功证据是相同服务/数据/权限下可复算的资源改善且服务折中可接受；不预填“必须降低 5%”作为调参验收。
未通过相同校准要求的方法仍报告，但不能把裸成本排序称作风险约束下优势。输出 main_table.csv、逐请求
差、校准状态和质量—成本图。

E2 收益增强检索
仅将 κ 设为 0，对同 300 条任务新增 300 条轨迹。其余预测器、支持阈值、场景数、偏好和门一致；邻居随距离
变化是预期机制。记录邻居变化、后续调用数、非正收益次数/比例、负收益次数、成本与失败数。非正收益比例
分母为实际后续尝试数，失败尝试也保留，使用真实已保留答案的参考质量变化作事后统计。
若无增益，要检查收益模型是否能区分动作、标准化是否压倒基础特征、邻居是否被历史结构过滤到极少来源；
不能直接把 κ=0 劣势当作必然事实。

E3 联合采样
对同 300 条新增 300 条轨迹，仅改 donor coupling：同一池分别抽答案结果块和资源环境块，权重规则/支持规

会意外改变所有其他随机性。

异。
E4 多步规划与净控制开销

14. 计算、标注与执行预算的估算办法
大模型预采集上限：1500 正式+100 开发任务，每条三个模型，共 4800 次独立调用。E6 另有最多 900 次动态调
用，实际次数由策略决定。网络变体若影响输出/超时而需要新生成，另计；不能把缓存复用承诺为全部真实场景
免调用。
按单次调用平均生成时间 t1.5、t7、t14 秒，预采集服务占用时间约 1600×(t1.5+t7+t14)/3600 小时。并发会影
响墙钟与排队，不直接降低总设备占用。编码与树模型训练通常小于生成和标注成本，但本机实际时间/内存需
M1/M2 微基准测量，当前不编造 GPU 小时数。
离线策略执行：主实验+两消融为 3300 条测试轨迹；11×400=4400 条校准轨迹；E5 聚焦三方法上限 2700 条条
件轨迹，E4 复用 E1。以上合计上限 10400 条回放轨迹，不含 D_V 搜索和开发诊断，不代表独立样本数。
人工成本可按“4800 答案×2 位评分者×每份平均评分分钟/60”计算，再加争议裁定。评分时间、分歧率和可
核验任务比例先在 10–20 条开发数据测量。不得让未经复核的自动裁判标签冒充真实质量保证。
资源配置还需确定：三种精确 Qwen 权重及设备/量化/框架、MiniLM 权重版本、链路测量或生成依据、自托管占
用费率、F0/V0 参考尺度、输出上限和超时处理。PDF 未报告的字段需新实验补齐并标明，不推断旧结果的运行
条件。

16. 第一批应落实的三项工作与最终交付标准
第一项，建立 v5_protocol 与正式数据契约：锁定 PDF 口径、三模型角色、成本定义、五分区、来源组与标签边
界；保留旧工程模式。
第二项，在 10–20 条开发任务上完成“相同原始输入→单次调用→双人评分→资源核对→安全回放”，并补齐时间
索引环境；同时写微树精确参考测试。此阶段不需要先运行 1500 条正式数据。
第三项，训练并冻结 D_Q 评分管线、实现真实文献基线适配，再进入 D_G 收益与联合库。新方法和强基线共享
执行/评估框架，但不混同其预测器设计。
最终验收不是只有主表：必须交付可运行源码与配置、来源/分区清单、精确模型与环境版本、评分裁定记录、冻
结包、完整校准结果、E1–E6 请求级轨迹、数学/资源接口测试、从日志重算图表的脚本，以及哪些风险主张尚不
能支持的明确说明。
本轮只形成计划和可读 PDF，不修改算法源码、不下载模型、不执行真实生成或大型实验。待进入实施时，先按
M0–M1 验收，再逐阶段扩大；模型部署与正式数据缺项不会用合成数据静默补齐。
