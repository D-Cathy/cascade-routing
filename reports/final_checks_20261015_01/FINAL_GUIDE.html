收尾检查与风险校准工具

本轮增加第7步的校准检查基础工具，以及第8步的实验就绪清单。代码回归通过；正式论文实验仍未完成。

新增内容和逻辑

文件用途
src/selection/v5/calibration.py冻结候选文件哈希与计划校准单位；检查结果完整性；计算单侧二项参考上界
src/selection/v5/final_checks.py校验任务契约、统计实际分区，并运行20条合成校准演示
tests/test_v5_calibration.py12项边界与完整性测试

先通过 freeze 保存候选文件和校准单位，再由 evaluate 读取结果。候选数量H来自冻结清单，使用 delta/H 修正多候选检查。输入结果必须覆盖全部候选与全部计划单位，不允许删除失败请求；有未知服务失败标签时不计算上界。D_T记录、未冻结候选、重复单位及文件变更会被拒绝。

服务失败输入必须由上游按低质量、超时、超预算、无有效答案的并集生成。当前工具检查输入格式与覆盖性，不负责从执行轨迹重新计算这个标签。候选文件应包含或引用并冻结所有依赖；目前仅核验显式传入文件，不递归追踪模型、配置依赖。

如何读懂结果

假设只有一个候选策略、20个独立单位、零次失败，95%单侧Clopper–Pearson参考上界为13.9108%。目标是10%，所以 passes_reference_bound=false。零次观察失败不意味着真实失败概率为零。多候选时修正后的上界更保守。

本轮20个校准单位完全是人工构造的fixture，未运行真实模型，也未评估真实策略。输出始终 risk_guarantee=false、selected_policy=null；不自动挑选部署策略。来源组ID唯一不能证明统计独立，文件哈希也不能证明冻结确实发生在观察结果之前。

实际验证结果

新增测试12 passed；完整回归169 passed，耗时5.81秒，退出0。检查入口运行退出0。真实模型调用0。

真实数据仍为20条development；D_Q、D_G、D_V、D_C、D_T均为0。readiness.json的分区数量来自输入文件，blocking_items是人工维护的项目缺项清单，不是自动审计全部论文实现的结论。

复验命令

在cascade-routing目录运行：

PYTHONPATH=src python -m pytest -q tests/test_v5_calibration.py
PYTHONPATH=src python -m pytest -q
PYTHONPATH=src python -m selection.v5.final_checks --dataset data/routerbench_v5_contract_20261014 --output reports/final_checks_manual_01

输出目录必须全新，已存在则拒绝覆盖。查看 readiness.json 的分区统计及 synthetic_calibration.json 的上界与false标记。演示正常退出表示软件流程运行成功，不表示正式实验已经就绪。

距离完整论文实验还有什么

需要完成未用于开发的正式来源审查及五路冻结；正式编码器、有效性标签与服务分类器；供体到当前任务的映射和动态模型支持阈值；论文完整前沿与强基线；候选冻结后的独立校准和测试；E1–E6、消融、链路压力测试与领域验证。

因此本轮完成的是收尾检查工具，不是把八步研究路线全部标成完成。普通离线验证已经执行，用户无需先接入大模型来复验本轮工具；真实领域标签、部署与实测资源仍需后续落实。
